# Local setup

## Requirements

- Docker Desktop (for the development stack)
- Node.js 26 or newer
- pnpm 12 (the pinned version is in `web/package.json`)
- JDK 25 and Maven 3.10.0; the wrapper `services/mvnw` pins Maven, so a local
  install is optional

## Environment

Copy the development template to the repository root once:

```powershell
Copy-Item infrastructure/.env.dev .env
```

`.env` is gitignored and contains development-only defaults. Never reuse those
credentials in a deployed environment. Vite development servers load the root
`.env`; site-local files override root values, and shell/IDE variables override
both. Only `VITE_` variables reach browser code. Restart a process after changing
environment files.

The template also sets `STUDIO_TEST_ADMIN_URL` and `STUDIO_TEST_ADMIN_ROLE`, the
migrator connection used by the PostgreSQL-gated web and Java suites. If a
native PostgreSQL already owns port 5432, change `POSTGRES_PORT` **and** the
port in both `DATABASE_URL` and `STUDIO_TEST_ADMIN_URL` together.

`pnpm test` loads the root `.env` when it exists, so the web integration suites
run without exporting anything. Java does not read `.env` automatically and has
no `APP_ENV_FILE` loader; supply variables through the shell or the IDE run
configuration, for example with an IDE environment-file plugin. To run the Java
persistence suites from PowerShell:

```powershell
$env:STUDIO_TEST_ADMIN_URL = (Select-String -Path .env -Pattern '^STUDIO_TEST_ADMIN_URL=').Line.Split('=', 2)[1]
services\mvnw.cmd -f services/pom.xml test
```

Rebuild Java services after changing the shared module.

## Run the whole stack

From the repository root:

```powershell
docker compose -f infrastructure/compose.dev.yaml --env-file .env up -d --build
```

| Application | URL |
| --- | --- |
| Studio | <http://localhost:8000> |
| Jublawoma | <http://localhost:8001> |
| Uncle-T | <http://localhost:8002> |
| Zelglihof | <http://localhost:8003> |
| Oliumbi (static placeholder) | <http://localhost:8004> |
| Identity | <http://localhost:8081> |
| Messaging | <http://localhost:8082> |
| Assets | <http://localhost:8083> |
| Mailpit (development email) | <http://localhost:8025> |

The compose stack runs PostgreSQL, Flyway, the one-shot role provisioning, the
services and the sites. PostgreSQL and the service ports are development-only;
they are not published in production.

## Frontend-only workflow

Keep infrastructure in Docker and run the web app natively:

```powershell
docker compose -f infrastructure/compose.dev.yaml --env-file .env up -d postgres flyway roles mailpit
cd web
pnpm dev:studio        # or dev:jublawoma, dev:unclet, dev:zelglihof, dev:oliumbi
```

Studio also needs identity and assets; delivery history needs messaging. Run
them in Docker or in the IDE. Public images need assets; queued email needs
messaging. Oliumbi needs only the database variables for its anonymous counter
and no other service; it is the smallest way to check the shared Vite/Tailwind
setup.

```powershell
docker compose -f infrastructure/compose.dev.yaml --env-file .env up -d identity assets messaging
```

## Run a built site

From `web/`, after `pnpm build`:

```powershell
node --env-file=../.env sites/studio/.output/server/index.mjs
```

Replace `studio` with another site as needed. Oliumbi needs `DATABASE_URL` and
`OLIUMBI_DATABASE_PASSWORD` for its anonymous counter; include `--env-file` when
you want counting to work in a built site (the page itself renders without it). Node loads the root
`.env`; shell variables win. Production builds do not load `.env`;
`pnpm --filter studio start` expects variables to be supplied externally.

## Database

Flyway migrations in `database/migrations/` are the schema source of truth. While
the system is pre-launch, migrations are edited in place, so recreate the local
database after a migration changes:

```powershell
docker compose -f infrastructure/compose.dev.yaml --env-file .env down -v
docker compose -f infrastructure/compose.dev.yaml --env-file .env up -d --build
```

Migrations create the roles `NOLOGIN` (nine in V001: the content roles, the
`oliumbi` counter role and the read-only `monitoring` role); the compose `roles`
service provisions the application roles' development passwords after migration.
Oliumbi writes only the shared analytics counter; its content schema stays empty.
If you created a database
without compose, run the documented `ALTER ROLE ... LOGIN PASSWORD ...`
statements once; see [database/README.md](../../database/README.md).

Never use the migrator's credentials for a web application. Each app configures a
fixed database role independently of its connection URL.

## Generated code

- **i18n:** edit `web/packages/i18n/messages/de-CH.json`. `pnpm generate` (from
  `web/`) is the only writer of the git-ignored Paraglide output. `pnpm typecheck`
  runs it first.
- **Route trees:** `src/routeTree.gen.ts` is committed and regenerated by the
  TanStack Router Vite plugin during `pnpm dev` and `pnpm build`. Commit it after
  changing routes.

## Common problems

| Symptom | Check |
| --- | --- |
| App cannot connect to PostgreSQL | role password matches the migrated database; restart after editing `.env` |
| Studio redirects to sign-in | identity URL and `*_INTERNAL_AUTHORIZATION_TOKEN` values |
| Images 404 locally | assets service running; `ASSETS_SERVICE_URL` |
| Messages stay pending | messaging service running; Mailpit on 1025; `MESSAGING_SMTP_*` |
| Studio cookie not set over HTTPS | `STUDIO_SECURE_COOKIES=true` |
| Typecheck fails on a route tree | regenerate with `pnpm dev`/`pnpm build`, commit the route tree |
| Java cannot see a new env var | supply it in the run configuration; Java does not read `.env` |
